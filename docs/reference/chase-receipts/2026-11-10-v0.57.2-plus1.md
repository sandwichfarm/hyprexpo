## Disposable rendering and lifecycle

Matching KVM/VirGL compositors on every target pass grid pointer/keyboard
selection and cancel, submap restoration, scrolling topology and pinned-window
preservation, exact no-op and injected mutation rollback, touch cancellation,
config reload, repeated unload/load/reopen including unload while open, and real
compositor exit with status zero.

Actual background pixels retain cover/contain/stretch, blur, cached reopening,
same-path replacement on reload, disabled/unreadable fallback, and cache cleanup
in grid and native scrolling overviews. Actual icon pixels prove all five
anchors with default background padding at tile edges, GTK-theme priority over
hicolor, malformed desktop-entry tolerance, same-path SVG replacement on reload,
validated absolute desktop icons, and cached-texture unload/reload.

The 0.57.2 two-output fixture also passes at 1280x720 scale 1 and 900x600 scale 1.5.
Local and foreign icons remain contained and centered on owner-captured previews,
including `on all` on both outputs. Foreign keyboard selection preserves workspace
ownership and leaves config health clean.

## Publication and coverage boundary

Normal no-revision HyprPM selection must be verified after the public pin
manifest lands, before tagging. The tag workflow builds the Arch artifact
separately; its actual downloaded bytes, tag/source/VERSION/ABI provenance,
rendering, cache lifecycle, physical unload to zero mappings, reload and clean
exit require independent acceptance. Publication outcomes belong in the release
notes alongside `release-provenance.txt`.

Nix/CMake API unload/reload and real exit pass; physical library unmapping is not
claimed for that binary because the same residency occurs on the prior baseline.
Nix-assisted HyprPM checks do not claim an unprepared generic distro install.
Physical touchpad gestures, HDR, rotated outputs and physical mixed-DPI hardware
remain outside this validation scope. Virtual mixed geometry and fractional scale
are covered. The daily desktop installation and saved HyprPM state are unchanged.
